# Farm Diet 검증 결과

검증일: 2026-10-03 (Asia/Seoul)

## 최종 재검수 및 접속 진단

`package.json`의 개발 명령은 `next dev --webpack --hostname 127.0.0.1`이며, 프레임워크는 Next.js입니다. 최초 검사에서 3000번 포트의 실행 중인 서버를 확인하지 못했습니다. 개발 서버를 다시 실행한 뒤 `Ready`, 실제 포트 3000, 동일 실행 프로세스 내 홈페이지 HTTP 200 응답을 확인했습니다. 서버는 검수 종료 시 계속 실행합니다.

다른 터미널 프로세스에서는 같은 주소 요청이 `connect ETIMEDOUT 127.0.0.1:3000`으로 실패했습니다. 따라서 서버 내부 응답과 사용자 미리보기의 접속 복구를 구분해야 합니다. 샌드박스 실행 환경 사이의 localhost 접근 문제로 보이나 정확한 원인은 미확정입니다. 사용자 측 일반 터미널에서 이 프로젝트 폴더로 이동해 `npm run dev`를 실행하고 표시된 주소로 접속하는 절차가 필요합니다.

이번 검수에서도 `npm run data:build`(1,127건·13작목), `npm test`(38개), `tsc --noEmit`, `npm run build`가 모두 통과했습니다. 새 정적 출력의 5개 페이지와 18개 참조 자산도 정상 응답했습니다. 9대 비용 중복 합산, 상위군 올림·경계 동점, 중앙값, 50건 지역 fallback, 사용자 입력만 300평 환산, 레이더 기준 100 및 0 기준 처리, What-if 계산에서 수정할 오류를 발견하지 못했습니다. UI와 기능 소스는 변경하지 않았습니다.

브라우저 도구는 기존 접속 오류 페이지의 `data:` URL을 보안 정책으로 차단했습니다. 우회하지 않았으며 360px 실화면 검증과 사용자 앱 미리보기 접속 확인은 미완료입니다.

테스트는 계산식·실제 전처리 결과와 컴포넌트 상태를 검증합니다. 빈 입력 거부, 간편 모드의 두 비용만 비교, 중복 선택 방지, 정밀 모드 9개 행·슬라이더, 0 임차료 표시, 직접 결과 페이지 방문 시 재입력 안내, 시뮬레이터 변경·초기화도 확인했습니다.

WebMCP 도구는 가상 DOM의 등록 인터페이스로 정상 입력·범위 오류·상태 보존을 검증했습니다. 실제 지원 브라우저에서의 등록·실행 검증은 완료하지 못했습니다.

실제 브라우저의 자동 화면 검증은 URL 보안 정책으로 거부되어 진행하지 않았습니다. 360px 대응 CSS를 구현했지만 브라우저 화면·폰트 확대·실제 레이더 표시의 시각 검증은 미완료입니다.

Sites 게시 준비의 소스 동기화 입력이 자동 승인 정책으로 차단되어 온라인 게시는 완료되지 않았습니다. 로컬 프로젝트와 정적 출력은 별도 제공하며, 게시 성공 URL은 아직 없습니다.

비용 빈 셀 3,106개는 회계 관계 검산 후 0 가정을 허용했습니다. 실제 무투입인지 미응답인지는 제공자 확인이 필요합니다. 지역 최소 50건은 운영 기준이며 통계적 안정성의 보장은 아닙니다.

최종 빌드는 생성된 `.next` 캐시에 명시적 파일 접근 권한을 부여한 뒤 성공했습니다. 이 Windows 샌드박스에서 재현 시 같은 경로의 권한이 필요할 수 있습니다. 단일 빌드 작업 프로세스를 사용하며, 일반 로컬 환경에서는 이 샌드박스 권한 설정이 통상 필요하지 않습니다.
